A **block definition** describes what a block **is**; the minion's `type` decides what is **done** with it. Each definition is one config file in `blocks/`. This page builds one from scratch.

## Quick start

1. Open the `/plugins/EcoMinions/blocks/` folder and copy `_example.yml` to a new file, e.g. `ebony.yml`. The file name is the definition ID.
2. Set `block` to the block it describes.
3. Add the keys that block needs, e.g. `plant` and `leaves` for a custom tree.
4. Run `/minions reload` and confirm no violation is reported for the file.
5. Point a minion's `target-blocks` at the block and confirm it works it.

:::tip
`_example.yml` is included as a reference and is **never loaded**, so copy or rename it to make a real definition. You can also organise definitions into subfolders inside `blocks/`, and they'll still load.
:::

## Naming and IDs

The file name without `.yml` is the definition ID, so `blocks/oak.yml` has the ID `oak`. The `block` key is what matches it to a target: `target-blocks` names `OAK_LOG`, not `oak`.

:::warning ID rules
IDs may only contain lowercase letters, numbers, and underscores (a-z, 0-9, _). No spaces, capitals, or hyphens, or the definition will not load.
:::

## The structure of a block

| Part | What it controls |
| --- | --- |
| **Block** | Which block the definition describes |
| **Growing** | What is planted to bring it back, and the tree it grows |
| **Mining** | Whether minions can target it, and how it is cut |
| **Rewards** | Its drops and XP |
| **Override** | Forcing a behaviour for this one block |

```yaml
# === Block: what this describes ===
block: OAK_LOG # The block this describes. Any block id, custom blocks included. Required.

# === Growing: bringing it back ===
plant: OAK_SAPLING # What is planted to bring it back: a sapling or a crop.
leaves: OAK_LEAVES # The canopy of the grown tree. Needed by woodcutters.
surface: GRASS_BLOCK # Optional. What must be underneath to plant here.
tree-pattern: oak # Optional. Which built-in tree shape to grow.

# === Mining: how minions treat it ===
mineable: true # Optional. Set false so no minion can target it. Defaults to true.
stacked-column: false # Optional. Whether it grows upward in a column, like sugar cane. Defaults to false.
promotes-to: "" # Optional. What targeting this block really means, e.g. seeds promote to the grown crop.

# === Rewards: drops and XP ===
drops: [] # Optional. The items one break gives, for custom blocks.
xp: 2-5 # Optional. The XP one break is worth, as a number or a range.

# === Override: forcing a behaviour ===
restore: tree # Optional. One of regen, replant or tree, beating the minion's type.
```

### Block

A block definition describes what a block **is**. The minion's `type` decides what is **done** with it, which is why the same `OAK_LOG` is felled by a woodcutter and regenerated by a miner with no extra config.

```yaml
block: OAK_LOG # The block this describes. Any block id, custom blocks included. Required.
```

:::info
`blocks/` ships empty, and that is normal. Vanilla is built in: every tree's sapling and leaves, wheat on farmland, cactus and sugar cane cut at their base, and the blocks that break too badly for a minion. Write a file only for a custom block, to change a built-in default, or to force a behaviour. A file always wins over the built-in definition for the same block.
:::

### Growing

What is planted to bring the block back, and the tree it grows.

```yaml
plant: OAK_SAPLING # What is planted to bring it back: a sapling or a crop.
leaves: OAK_LEAVES # The canopy of the grown tree. Needed by woodcutters.
surface: GRASS_BLOCK # Optional. What must be underneath to plant here.
tree-pattern: oak # Optional. Which built-in tree shape to grow.
```

`surface` also turns on `lift-regen` for minions targeting this block, which is how a crop gets its farmland back with no extra config. `tree-pattern` defaults to the definition's ID, see [Tree shapes](configuring-a-woodcutter#tree-shapes).

### Mining

Whether minions can target the block, and how they cut it.

```yaml
mineable: true # Optional. Set false so no minion can target it. Defaults to true.
stacked-column: false # Optional. Whether it grows upward in a column, like sugar cane. Defaults to false.
promotes-to: "" # Optional. What targeting this block really means, e.g. seeds promote to the grown crop.
```

Set `mineable: false` for blocks that break badly, such as amethyst buds, dripstone or vines. A minion targeting one is reported at startup. A `stacked-column` block is only ever cut at its base, taking the whole column in one action.

### Rewards

What one break gives the minion.

```yaml
drops: # Optional. The items one break gives, for custom blocks.
  - "itemsadder:ruby"
xp: 2-5 # Optional. The XP one break is worth, as a number or a range.
```

Live mining already uses the drops of vanilla and EcoItems blocks. Set `drops` for other plugins' custom blocks, or to override them. Offline catch-up always needs `drops` for a custom block, as its drops cannot be rolled while nobody is online, so without it the block gives nothing offline. Vanilla ores already have their vanilla XP. Where XP goes is set by `minion.xp.mode` in [Plugin Config](../plugin-config).

### Override

Forces one behaviour for this block, whatever the minion's `type` is. Almost never needed.

```yaml
restore: tree # Optional. One of regen, replant or tree, beating the minion's type.
```

`regen` puts the block back exactly as it was, `replant` plants it again as a young plant, and `tree` fells it and plants a sapling. An override the definition cannot do, such as `tree` with no `leaves`, is reported and ignored.

:::tip Troubleshooting
- **Definition not used?** `block` must match the id in the minion's `target-blocks`, not the file name.
- **Woodcutter rejected at startup?** A custom log needs both `plant` and `leaves`.
:::
